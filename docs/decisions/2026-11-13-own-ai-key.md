# A student's own AI key

Asked by Erick on 2026-11-13. Design decided by the master session the same day. Branch `own-ai-key`. Code in `frontdoor/own-key/`, migration `frontdoor/supabase/migrations/20261113000100_own_ai_keys.sql`.

## What

A hosted student may paste their own Anthropic API key on a new Account page, `/account/ai-key` ("Your own AI key"). From then on the tutor's model calls for that student go to Anthropic with the student's key, so Anthropic bills the student, not North Aero. A Remove button goes back to North Aero's key at once.

Not built: signing in with a ChatGPT or Claude subscription. That waits on a terms check. The page takes Console API keys only (`sk-ant-api..`); a subscription token (`sk-ant-oat..`) or an Admin key is refused as the wrong format.

## Why

Today North Aero's key pays for every student's AI use. A student who brings a key pays for their own.

## How it works

1. **The key stays in the front door.** The tenant server never gets it, and it is never written to the volume. The tenant keeps calling the meter with its pass key. For each Anthropic call (`/v1/messages` and `/v1/messages/count_tokens`) the meter asks `own-key/service.ts` which key to use, and sends the call with the student's key when one is saved. Searches still use North Aero's Tavily key.
2. **Saving.** The page posts to `POST /_frontdoor/ai-key` (behind the tutor's login and a same-origin check, like the session-text switch). The front door checks the format, then makes one free call, `GET https://api.anthropic.com/v1/models?limit=1`, with the key. Only a 200 saves it. A student gets at most 5 checks in 10 minutes, so the page cannot be used to test many keys. The answer is a redirect back to the page with `?saved=1` or `?error=<reason>`. The key is never put in an address.
3. **Status.** `GET /_frontdoor/ai-key` and the page show only whether own keys are on, and the saved key's last 4 characters and date.
4. **No silent fallback.** If Anthropic refuses the student's key, the call is not sent again with North Aero's key. The meter answers the tenant with a 403 `permission_error` (the Anthropic SDK does not retry it), and the tutor shows the message, the same way it shows the pause message:
   - 401 or 403: "Anthropic refused your own AI key. Check it on the Account page, or remove it to use North Aero's."
   - 402, or a 400 that says the credit balance is too low: a no-credit message.
   - 429: a too-many-requests message.
   - Any other error passes through as Anthropic sent it, as before.
   - A saved key that cannot be decrypted (the secret was changed) refuses the call with "Your saved AI key can't be read. Save it again on the Account page, or remove it to use North Aero's."
5. **Database outage.** The meter reads the key on every call, so a save or removal takes effect at once. It follows the pause check's rule: the last answer per student is remembered for 1 minute and used only when the database is down or slow. With nothing remembered, the call is refused with the usual "Usage tracking is briefly unavailable" (503). It never falls back to North Aero's key.
6. **Usage and the cost cap.** Own-key calls still write `model_usage` rows, at list price, with the new column `own_key = true`.
   - The alert and the $89 automatic pause count North Aero's cost only (`pause/limits.ts`, scope `north-aero`). An own-key call does not start a cost check.
   - The Owner dashboard keeps own-key spend apart: an "Own key" mark on the student, an "Own-key spend" figure per student and in the totals. Model cost, cost and margin are North Aero's only.
   - A pause still applies to a student with an own key (an Owner pause, an autopause from earlier North Aero cost, or retention). A paused student can still save or remove a key.
   - Plans and prices are unchanged, and so is the trial's study-time limit. The trial's $10 cost cap (PD2) counts North Aero's cost only: own-key calls are left out (Erick, 2026-11-13: "No it shouldn't").
7. **Off switch.** Without `LH_OWN_KEY_SECRET` the feature is off: the page says so plainly, nothing is read or saved, and every call uses North Aero's key. A key saved earlier then stays stored but unused, and the page still offers Remove.

## How the key is kept safe

- **Encrypted at rest.** AES-256-GCM (`own-key/crypto.ts`), with a fresh 12-byte nonce per key and the tenant id as associated data, so a row copied to another tenant cannot be opened. The table `own_ai_keys` holds the ciphertext, nonce, tag, last 4 characters, provider (`anthropic`) and dates.
- **The secret is outside the database.** `LH_OWN_KEY_SECRET` is a Railway variable: 32 random bytes in base64 (`openssl rand -base64 32`). A copy of the database alone, a Supabase backup included, cannot be read. Set but malformed, the front door refuses to start, naming the variable and never its value. Tenant servers never get it (they get only the supervisor's short allowlist).
- **Changing the secret** makes every saved key unreadable. Each student must save their key again. Keep a copy of the secret outside Railway, like `LH_TRIAL_HASH_KEY`.
- **Row-level security** is on for `own_ai_keys`, with no allow rules and no rights for `anon` and `authenticated`; only the server (`service_role`) reads and writes, as for every table. Deleting a tenant (day 91) deletes its key.
- **Never logged.** The log filter (`log-hygiene/filter.ts`) now hides any `sk-...` key as `[key]`, in the code's own message, later arguments, error messages and codes, objects and crash reports. The front door's own log lines name tenants, statuses and error classes only. Request bodies are never logged.
- **Never shown whole.** The API and the page return only the last 4 characters. The dashboard shows no part of a key, only the "Own key" mark.
- **Not on the volume.** Nothing about the key is written under the volume, so the nightly tenant copies and the export never hold it. The meter's pending and rejected usage files hold the `ownKey` flag only.

Tests: `tests/frontdoor-own-key.test.ts` (sealing, the secret, the key format, the service's outage rule and check limit, the refusal messages, the log filter, the database, and the whole flow end to end through the wired front door with a fake Anthropic) and `tests/frontdoor-own-key-page.test.tsx` (the page).

## Deploying

1. Apply the migration to Supabase (Erick's yes). It is safe for the code already running: a new table, and a new column with a default.
2. Deploy. The code also works before the migration is applied: North Aero's calls are stored as before, the cost reads fall back to the old queries, and a key read finds none (logged once).
3. Set `LH_OWN_KEY_SECRET` in Railway to turn the feature on. Keep a copy outside Railway.
4. The privacy notice and terms need new sentences before students use it (Erick's legal drafts).

## What is not built

- Signing in with a ChatGPT or Claude subscription (waits on a terms check).
- OpenAI keys. What they would take:
  - Upstream routes only its Anthropic provider through the meter (`LH_ANTHROPIC_BASE_URL` in `src/agent/models.ts`). OpenAI calls would need the same, with an upstream change logged in `docs/upstream-changes.md`.
  - The meter would need OpenAI's paths, its usage format (streamed and not), its error codes (401, 429 `insufficient_quota`) and `openai:` prices.
  - The tutor's per-role models (Strong, Cheap, Vision) are the Owner's Anthropic models in each tenant's `settings.json`, and the route guard keeps students from changing them. A student with only an OpenAI key would need OpenAI models for their own tenant, which changes how the tutor teaches (the prompts are tuned on Claude) and is the Owner's call.
  - `own_ai_keys` allows one Anthropic key per student; a second provider needs `(tenant_id, provider)` as the key and a wider provider check.
- Own-key use of web search: searches stay on North Aero's Tavily key and fees.
- A different price or plan for students with their own key. Pricing is Erick's call.
